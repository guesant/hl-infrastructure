# Engenharia de requisitos

Engenharia de requisitos é o conjunto de atividades usado para descobrir, compreender,
negociar, especificar, validar, priorizar, rastrear e alterar necessidades de um sistema.
Ela não é somente escrever uma lista de funcionalidades. O trabalho precisa conectar
problema, pessoas, regras, comportamento observável, propriedades de qualidade, restrições,
risco e evidência de que o resultado atende ao que foi combinado.

## Distinções que evitam confusão

Um requisito é uma necessidade, capacidade, condição ou restrição que precisa ser atendida.
Uma especificação é uma forma de registrar essa necessidade. Um backlog é uma coleção
ordenada de itens de trabalho que ajuda a decidir o que será explorado, construído,
validado ou descartado. Um teste é uma forma de obter evidência sobre um comportamento.

Essas coisas podem se relacionar, mas não são sinônimas. Uma user story não é o requisito
inteiro, um cenário BDD não é necessariamente um teste de unidade, e uma task não é uma
unidade de valor para o usuário. Misturar os níveis produz backlog grande, rastreabilidade
fraca e decisões difíceis de revisar.
