# Distribuições Kubernetes

Kubernetes mantém aplicações em containers a partir de recursos declarativos enviados à sua API: em vez de descrever uma sequência de comandos, o usuário declara o estado desejado em objetos como Deployments e Services, e controllers observam continuamente esses objetos, comparam com o estado atual e agem para aproximar os dois, o ciclo chamado de reconciliação. Um `Pod` é a menor unidade executável, reunindo um ou mais containers que compartilham rede e volumes; um `Deployment` mantém a quantidade desejada de réplicas e coordena atualizações; um `Service` dá um nome e endereço estáveis para um conjunto variável de Pods; um `Namespace` separa logicamente recursos; um `Secret` guarda dados sensíveis, sem ser criptografado automaticamente só por existir como tal; um CRD estende a API com um novo tipo de recurso, como `Certificate` ou `Application`.

Kubernetes é uma especificação, não um produto único; cada distribuição a implementa com opiniões diferentes sobre o que empacotar. K3s e RKE2, ambas da Rancher/SUSE, fazem escolhas opostas: K3s é minimalista e opinativo, já vem com Flannel, Traefik e etcd embarcado, um binário de dezenas de MB pronto em segundos, ideal para desenvolvimento e clusters pequenos, mas sem hardening FIPS/CIS nativo nem certificação de compliance. RKE2 não empacota CNI, ingress nem storage por padrão, cada escolha é explícita, e já vem com hardening alinhado ao CIS Benchmark e suporte a FIPS, a escolha certa quando compliance formal é um requisito real, ao custo de mais configuração manual e mais consumo de recursos. Um padrão comum usa K3s em desenvolvimento e RKE2 em produção regulada, já que ambas expõem a mesma API e são agnósticas quanto ao CNI das aplicações; migrar de uma para outra é um redeploy num cluster novo, não um upgrade in-place.

Outras distribuições otimizam para cenários distintos. **k0s**, da Mirantis, é modular e leve, distribuído como binário único altamente customizável, componente por componente, adequado para IoT e edge onde a customização compensa o esforço extra, mas menos maduro e com comunidade menor. **kubeadm** é a ferramenta oficial de bootstrap, sem opinião nenhuma sobre rede, storage ou ingress, valiosa para aprender Kubernetes a fundo ou para customização extrema on-premises, ao custo de setup manual em cada etapa. **MicroK8s** empacota Kubernetes como um pacote snap, com etcd, CNI e complementos integrados, instalado com um único comando, conveniente para desenvolvimento local num laptop, mas limitado ao ecossistema snap e não pensado para escalar além de uso local.
